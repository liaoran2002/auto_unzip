# Auto Unzip

一个自动化文件解压工具，支持多种压缩格式和分卷文件，带有图形界面和命令行接口。

## 功能特点

### 📦 支持的格式

- **主流压缩格式**: 7z、RAR（含 RAR5）、ZIP
- **分卷文件**: `.part1.rar`/`.part2.rar`、`.r00`/`.r01`、`.7z.001`/`.7z.002`
- **其他格式**: tar、gz、bz2、xz、zstd、cab
- **加密文件**: 支持密码列表自动尝试

### ⚡ 核心功能

- **自动化处理**: 自动识别压缩文件并递归解压嵌套压缩包
- **支持拖入文件夹**: 拖一个文件夹进来，自动解压里面所有压缩包到各自所在目录
- **多线程**: 4 个并发工作线程；文件夹里的多个压缩包会**并行**处理
- **智能重命名**: 同名文件自动改名（`_1`、`_2`…），**绝不覆盖**已有文件
- **数据安全**: 只有全部文件成功取出后，才删除原压缩文件和分卷
- **实时日志**: 完整的操作记录和状态显示
- **多进度条**: 正在解压几个包就显示几条进度（左文件名｜中进度条｜右百分比），
  解压完该条自动消失
- **图种支持**: 能识别并解压"图片里附带压缩包"的图种（JPG/PNG 里藏 ZIP/RAR）
- **GUI 界面**: 直观的图形界面
- **命令行**: 支持批量处理多个文件

### 🎯 设计亮点

- **格式靠文件头识别**: 不靠扩展名猜，因此不会误伤 docx/xlsx/jar 等"内里是 ZIP"的文档
- **同名冲突不丢数据**: 冲突自动改名，而不是覆盖或报错
- **并行也不会互相覆盖**: 多个包同时解到同一目录时，"挑名字 + 搬过去"是原子的
- **失败必保留原包**: 搬运失败时原压缩包一定留着，避免静默丢数据
- **按条件递归**: 解压结果只有"一个压缩包"或"一组分卷"时才继续往里解，
  避免把用户原本放在目录里的压缩包也一并解掉
- **跨平台兼容**: 支持 Windows 系统

## 安装和要求

### 系统要求

源码安装要求：

- Windows 7/8/10/11
- Python 3.6+（用于运行源代码）
- `7z.exe` + `7z.dll`（**两个文件都要**，放在程序同一目录）

**成品（打包后）要求：**

- Windows 7/8/10/11
- 无需另装 7-Zip，引擎已随包附带

### 文件结构

源码文件结构如下：

```
auto_unzip/
├── auto_unzip.py       # 主程序文件
├── 7z.exe              # 7z 命令行程式（完整版）
├── 7z.dll              # 7z 的编解码库（必需，缺了 7z.exe 无法工作）
├── passwords.txt       # 密码列表文件（可选）
└── README.md           # 项目说明文档
```

> ⚠️ `7z.exe` 与 `7z.dll` 必须成对出现且在同一目录。
> `7z.exe` 自身不含编解码器，它靠 `7z.dll` 才能解压；
> 少了 `7z.dll` 就只能靠系统已安装的 7-Zip 兜底，在别人机器上会失败。

成品文件结构如下：

```
auto_unzip.exe
7z.exe
7z.dll
passwords.txt
```

### 运行方式

#### 方法1：直接运行可执行文件

```bash
auto_unzip.exe
```

#### 方法2：使用Python运行

```bash
# 处理单个文件

# 处理多个文件
python auto_unzip.py file1.rar file2.7z

```

#### 方法3：命令行参数

```bash
# 处理单个文件
auto_unzip.exe file.zip

# 处理多个文件
auto_unzip.exe file1.rar file2.7z
```

## 使用指南

### 1. 基本使用

1. 把压缩包**拖放到 `auto_unzip.exe` 图标上**（也可用命令行参数）
2. 程序会自动开始解压
3. 解压完成后窗口会自动关闭

> 说明：本程序用的是 tkinter，**不支持把文件拖进窗口内部**。
> 请拖到 exe 图标上，或直接用命令行。

#### 拖入整个文件夹

可以直接把一个**文件夹**拖到 exe 上：

- 程序会找出文件夹里（含各级子目录）的所有压缩包；
- 每个压缩包解压到**它自己所在的目录**；
- 多个压缩包会**并行**处理，进度区同时显示多条进度；
- 文件夹里的普通文件不会被动。

```bash
# 命令行同样支持传文件夹
auto_unzip.exe "D:\Downloads\待整理"
```

### 2. 密码文件配置

创建 `passwords.txt` 文件并放在程序同一目录下：

```txt
# passwords.txt 示例
123456
password
123abc
# 以 # 或 ; 开头的行会被忽略
```

程序会自动尝试密码列表中的所有密码，无需手动输入。

### 3. 界面说明

#### 日志区域

- 显示详细的操作流程
- 显示密码尝试结果
- 显示文件处理状态

#### 状态栏与进度区

- 状态栏实时显示**解压次数**和**待处理任务数**
- 进度区**每个正在解压的包各占一行**：左边文件名、中间进度条、右边百分比
- 某条对应的包解压完，那条进度就消失
- 单条进度里：0-80% 是解压、80-100% 是搬移文件阶段
- 文件名过长会自动中间省略（保留头尾）

### 处理流程

1. 检查输入参数，确定要处理的文件或文件夹
2. 按**文件头**识别真实压缩格式
3. 为每个压缩包在其**所在目录**建临时提取目录
4. 依次用「无密码」和密码表中的密码尝试解压
5. 把文件从临时目录搬到压缩包所在目录（同名自动改名）
6. **只有全部搬出成功**，才删除原压缩包和分卷
7. 按条件递归：解压结果只有"一个压缩包"或"一组分卷"时继续往里解
8. 清理临时目录

#### 线程管理

- 4 个工作线程同时处理文件
- **拖入文件夹时**，文件夹里的每个压缩包会拆成一个独立任务，真正并行
- 线程安全的队列系统
- 多个包同时解压到同一目录时，"挑名字 + 搬过去"用锁保护，不会互相覆盖
- 单个任务出现未预期异常时不会打死线程，也不会丢任务
- 所有任务完成后自动关闭（可用参数调整延迟）

#### 递归规则

只有下面两种情况会继续往里解：

- 解压结果里**恰好只有一个压缩包**；
- 解压结果**是一组分卷**（`.001`/`.r01` 加若干分包）。

其他情况（结果里混着普通文件、或好几个互不相关的包）就停下，
避免把用户原本就放在那里的压缩包也一并解掉。

> 如果直接拖入的是非首卷（如 `.003`），程序会自动改用同组的首卷解压。

#### 临时文件

- 临时目录建在**压缩包所在目录**下（同盘，保证搬移不跨卷）
- 名称为 `tmp_` + 随机串，并做撞名检测
- 无论成功失败都会清理

#### 命名规则

- 同名文件自动改名：`name.txt` → `name_1.txt` → `name_2.txt`…
- 同名目录自动合并

### 配置参数

您可以在代码中修改以下配置：

```python
max_attempts = 20         # 最多往内嵌套解压多少层（不是"总共解几个包"）
max_workers = 4           # 最大线程数
temp_dir_prefix = 'tmp_'  # 临时目录前缀
extract_timeout = 1800    # 单次解压超时（秒），防止卡死
progress_stall_s = 300    # 多久没有进度就认为卡住并中止
protect_documents = True  # 跳过 docx/xlsx/pptx/jar 等文档容器
scan_polyglot = True      # 识别"图种"(图片里附带的压缩包)
show_progress = True      # 显示进度条
progress_interval_ms = 120  # 进度条刷新间隔
PROGRESS_NAME_PX = 250    # 进度行里文件名一栏的像素宽度
close_delay_ms = 1500     # 全部完成后延迟多少毫秒关窗
```

支持的格式由文件头识别（`MAGIC_SIGNATURES`），不依赖扩展名：

```python
MAGIC_SIGNATURES = (
    (b'7z\xbc\xaf\x27\x1c', '7z'),
    (b'PK\x03\x04', 'zip'),
    (b'Rar!\x1a\x07\x00', 'rar'),
    ...
)
```

### 自行打包

如果您需要修改参数配置，您可以使用 PyInstaller 打包。

#### 打包步骤

1. 确保已安装 PyInstaller：
   ```bash
   pip install pyinstaller
   ```


> 若想排查启动问题，打包时可临时用 `--console` 观察输出。

## 常见问题

### Q: 程序提示「没找到可用的 7z 解压引擎」？

A: 请确认 `7z.exe` **和** `7z.dll` 都在程序同一目录下。

- 只放 `7z.exe` 是不够的：它自己不带编解码器，必须配 `7z.dll`；
- 如果系统装过 7-Zip，本机可能"看起来能用"，但**换台没装的机器就会失败**。

### Q: 无法解压 RAR？

A: RAR 需要完整版引擎。请把 7-Zip 官方安装目录里的 `7z.exe` 和 `7z.dll`
一起复制到本程序同目录。注意 `7za.exe`（独立版）**不支持 RAR**，别用它替代。

### Q: 程序没有反应？

A: 请确保：

- `7z.exe` 与 `7z.dll` 在正确位置（同一目录）
- 文件路径不包含特殊字符
- 程序有足够的权限

### Q: 密码尝试失败？

A: 请检查：

- `passwords.txt` 文件格式正确（每行一个密码）
- 密码包含在列表中
- 密码区分大小写

### Q: 解压后原压缩包没被删除？

A: 这通常是**保护机制生效**了，日志里会有「原压缩包保留不删」的提示。
常见原因是目标目录已有同名**目录**挡住了文件，或有文件被占用。
处理办法：移开冲突的同名目录后重试；原包一直留着，不会有数据丢失。

### Q: 图片也能解压吗（图种）？

A: 能。常见的"图种"是往 JPG/PNG 尾部附加 ZIP/RAR，本程序会自动识别：

- 日志里会显示「检测到图种(文件里含压缩包)」；
- 解压出的文件同样落在图片所在目录；
- 普通图片、视频、文本**不会被误碰**（7z 判定不通过就直接跳过）。

支持的类型：jpg/jpeg/png/gif/bmp/webp/tif/ico 等图片，以及少数 mp3/mp4/pdf 等。
如需关闭此功能，把 `scan_polyglot` 设为 `False`。

### Q: 进度条不动 / 长时间没反应？

A: 进度条解析的是 7z 自己输出的百分比，所以：

- 解压阶段（0-80%）会随进度推进；
- 搬移文件阶段（80-100%）按文件数推进；
- 若超过 `progress_stall_s`（默认 300 秒）完全没有进度，程序会主动中止，
  避免坏包把线程卡死。

### Q: 拖入一个文件夹会怎样？

A: 程序会：

1. 找出该文件夹**及其各级子目录**里的所有压缩包；
2. 每个压缩包解压到**它自己所在的目录**；
3. 多个压缩包**并行**处理，进度区同时显示多条进度；
4. 文件夹里的普通文件原样不动。

### Q: 解压出来的东西里还有压缩包，会继续解吗？

A: 只在两种情况下继续：

- 解压结果里**只有一个压缩包**；
- 解压结果**是一组分卷**（`.001` / `.r01` 加若干分包）。

如果结果里混着普通文件、或有多个互不相关的包，就停下来 ——
这是为了避免把您**原本就放在那个目录**里的压缩包也一起解掉。

### Q: 解压速度慢？

A: 可以尝试：

- 减少并发线程数
- 关闭其他占用系统资源的程序
- 确保有足够的磁盘空间

## 注意事项

1. **文件安全**: 程序在解压成功后会删除原压缩文件，请确保备份重要文件
2. **同名文件不会被覆盖**: 会自动改名为 `_1`、`_2`，请留意这类新文件
3. **密码安全**: 密码文件明文存储，请妥善保管
4. **分卷文件**: 所有分卷必须在同一目录
5. **文档不会被误拆**: docx/xlsx/pptx/jar/apk/epub 会被自动跳过
